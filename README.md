# Тёмный архив

Продолжение сайта-блога Артёма: React/Vite, Node.js API и PostgreSQL. Существующий репозиторий и адрес Vercel сохранены. Статьи больше не зависят от браузера автора: публикации, аккаунты, обсуждения и личная библиотека хранятся на сервере.

## Реализовано

- Чтение без регистрации, поиск, тёмная/светлая тема, мобильная вёрстка, размер текста.
- Отдельные адреса историй, серии с номерами частей и переходами между ними.
- Регистрация и вход: scrypt-хэши, HttpOnly-cookie, серверные роли, ограничения попыток, проверка источника запросов. Демо-вход `admin / 1234` удалён.
- Общие лайки и комментарии; удаление комментариев их автором или администратором.
- Закладки и место чтения с синхронизацией для аккаунта. Гость сохраняет их только на своём устройстве. Гостевые закладки копируются в аккаунт при входе; гостевые позиции чтения не переносятся.
- Кабинет автора: CRUD статей, публикация/черновики, создание серий, связывание частей, письма читателей.
- Экспорт текстов/обложек и импорт JSON/статей прежнего прототипа. Импорт всегда создаёт черновики и пропускает существующие адреса.
- Фото с подписями в тексте, ссылка на оригинал Дзена.
- Автоматические миграции, динамический sitemap опубликованных статей, конфигурация Vercel и Docker Compose.

## Запуск без облачных аккаунтов

Нужен Node.js 22 или новее. Для локальной разработки используется **PGlite** — PostgreSQL в одном процессе, с данными в `.data/postgres`. Папка исключена из Git. Не запускайте два процесса с одной локальной базой одновременно.

```bash
npm ci
npm run admin:create
npm run dev
```

`admin:create` спрашивает новый логин и пароль с **скрытым вводом**. Пароль не передаётся через командную строку. Создание администратора не изменяет существующие аккаунты. Откройте `http://localhost:5173`, войдите и выберите «Кабинет автора».

Для собранной версии:

```bash
npm run build
npm start
```

Она доступна на `http://localhost:3001`. Если используете `.env`, `SITE_URL` должен совпадать с адресом браузера (5173 для разработки, 3001 для собранного сайта).

## Vercel: подключить серверное хранилище

Продакшен **требует внешнюю PostgreSQL**. Данные в файловой системе Vercel не сохраняются надёжно, поэтому автоматический переход на локальную базу в продакшене запрещён.

1. В существующем проекте `dark-archive` подключите PostgreSQL (например, Neon или Supabase).
2. Добавьте серверную переменную `DATABASE_URL` с URL подключения. Для serverless используйте URL пула подключений. Никогда не добавляйте `VITE_` к имени этой переменной, не вставляйте секрет в GitHub или чат.
3. В окружении Production задайте `SITE_URL=https://dark-archive.vercel.app` (или фактический основной домен). Для Preview не задавайте production-адрес: без `SITE_URL` проверяется текущий домен запроса.
4. Для создания автора на локальном компьютере добавьте тот же `DATABASE_URL` в исключённый из Git `.env`, выполните `npm run admin:create`, затем уберите секрет с компьютера, если он больше не нужен.
5. Выполните redeploy. Миграции запускаются автоматически при первом API-запросе и не создают администратора автоматически.
6. Проверьте `/api/health`, регистрацию двух читателей, публикацию и чтение в другом браузере.

`vercel.json` маршрутизирует `/api/*` в одну функцию, пути историй — в SPA, robots и sitemap — в API. Миграции включаются в serverless-артефакт. При недоступном сервере интерфейс показывает сохранённые на устройстве статьи прежней версии либо два исходных рассказа; вход, лайки и обсуждения недоступны. Это аварийное чтение, а не сохранение серверных действий в браузер.

## Перенос старых статей

В том браузере, где редактировалась старая версия, сохранённый массив `articles` оставлен без изменений. Скачайте его кнопкой внизу сайта либо войдите автором и используйте «Перенести статьи → Из старой версии». При импорте проверьте черновики и опубликуйте нужные материалы.

**Автоматического переноса всех публикаций Дзена пока нет.** Доступны JSON-импорт, вставка текста, изображений и ссылка на оригинал. Статей, которых нет в исходном коде, сайт не выдумывает. Старые клиентские аккаунты не признаются серверными: зарегистрируйтесь заново. Их открытые пароли и флаг администратора удаляются из браузерного хранилища при запуске новой версии.

Экспорт из кабинета сохраняет статьи и сведения о сериях, а не полную резервную копию PostgreSQL. Для восстановления всей БД (аккаунты, обсуждения и библиотека) используйте резервные копии провайдера или `pg_dump`. Импорт принимает статьи; серии надо сначала создать и выбрать вручную для материалов из старого сайта. Для переносов между базами удалите `seriesId`/`episode` из статьи или используйте полную резервную копию БД.

## Формат текста

Пустая строка разделяет абзацы. HTML не исполняется.

```text
Первый абзац.

## Подзаголовок

![Подпись и источник фото](https://example.org/photo.jpg)
```

Изображения пока подключаются по HTTPS-ссылке: собственной загрузки/хранения файлов нет.

## Docker

В `.env` задайте `POSTGRES_PASSWORD` (длинный URL-safe пароль из букв и цифр) и `SITE_URL`. Для локального запуска подойдёт `http://localhost:3001`. Для внешнего доступа используйте HTTPS и соответствующий домен. PostgreSQL не публикует порт наружу; web слушает только localhost, перед ним нужен обратный прокси для внешнего доступа.

```bash
docker compose up -d --build
docker compose exec web node scripts/create-admin.mjs
```

Данные PostgreSQL живут в томе `postgres_data`. Не выполняйте `docker compose down -v`, если данные нужно сохранить.

## Проверка

```bash
npm test
npm run build
```

Тесты используют отдельную временную PostgreSQL/PGlite-базу и реальные HTTP-запросы: вход/выход, права, скрытые черновики, серии, лайки, библиотека, комментарии, импорт, ограничения запросов и сохранность после перезапуска. Отдельный облачный PostgreSQL и Docker в текущем окружении не проверены. Браузерная проверка ещё требуется перед выпуском. Пароль можно сменить административно; формы восстановления по почте пока нет. Мета-теги обновляются клиентом, серверного рендеринга статей для SEO пока нет.
